# 易通遥（EzyLink）

一套「手表 / 手机 ↔ 电脑」远程控制方案，通过 **WiFi 直连**控制电脑的 **PPT 放映**，  
以及执行**锁屏 / 睡眠 / 关机 / 重启 / 开机（WoL）**&#x7B49;基础操作。

```
┌──────────────┐   WiFi (TCP, JSON)   ┌──────────────┐
│ 手表 APK      │ ───────────────────▶ │  Windows 端   │
│ 手机 APK      │                      │  (TCP 服务)   │
│ (Android)    │ ◀─────────────────── │  执行指令      │
└──────────────┘                      └──────────────┘
   发送指令                               → PPT 快捷键
                                        → 锁屏/关机/重启…
                                        → WoL 接收由手表/手机主动发起
```

## 离线直连（不需要路由器 / 不需要互联网）

**结论：手机 / 手表与电脑只要在同一条网络链路里就能用，这条链路可以是家里路由器、电脑自己开的热点，或手机开的热点，双方都不需要接入互联网。**

推荐做法（完全离线）：

1. 电脑端主界面「连接信息」区 → 点 **开启移动热点设置** → 在系统设置里打开「移动热点」。
2. 回到易通遥点 **刷新**，界面会显示热点已开启，并给出推荐的连接地址（通常是 `192.168.137.1`）。
3. 手机 / 手表连上这台电脑的热点。
4. 手机 / 手表端打开易通遥 → 设置页点 **搜索电脑**，会自动列出电脑（UDP 广播发现，端口 **7789**）；也可以手动填第 2 步的地址。
5. 首次连接输入电脑端显示的配对码，之后**打开 App 就自动连好，可以直接用**。

电脑开不了热点、或手机连不上电脑所在的 WiFi 时：见下一节「手机热点自建局域网」。

> 若「搜索电脑」搜不到或连上无响应，先点电脑端的 **防火墙放行** 按钮（放行 TCP 7788 与 UDP 7789）。这是最常见的原因。安装器安装时已自动添加该规则。

## 手机热点自建局域网（电脑无热点 / 手机连不上同一 WiFi）

**适用**：电脑没有蓝牙、开不了移动热点，手机也连不上电脑所在的 WiFi，但**电脑有 WiFi 网卡**（能连 WiFi 就行，不需要能开热点）。

让手机当热点源，电脑和手表都作为客户端连上去，三者就进了同一个局域网。用的还是原来的 TCP `7788` + UDP `7789`，**软件不需要任何改动**，也不需要互联网、路由器或蓝牙。

```
手机（个人热点，例如 192.168.43.1）
 ├── 电脑（WiFi 客户端，192.168.43.x）← 易通遥服务在这里
 └── 手表（WiFi 客户端，192.168.43.x）
```

步骤：

1. **手机**：设置 → 个人热点 / 便携式 WLAN 热点 → 打开，记下名称与密码。热点只负责建一个本地局域网，**手机不需要有互联网、不需要开移动数据**。
2. **电脑**：WiFi 列表里连上这个热点。命令行执行 `ipconfig`，查看「无线局域网适配器 WLAN」的 IPv4（Android 热点常见 `192.168.43.x`，部分机型是 `192.168.137.x`）。
3. **电脑端易通遥**：点 **启动服务** → **刷新**，「设备连接地址」会优先显示热点网段的地址；也可点 **扫码连接**，在窗口里切换到热点网段那张二维码。
4. **手表**：设置 → WiFi → 连上**同一个**手机热点（华为手表需在「标准模式」，超长续航 / 仅作为手表模式下 WiFi 不可用；只支持 2.4GHz）。
5. **手机 / 手表端易通遥**：设置页点 **搜索电脑**（UDP 7789 广播，同一热点内可通）自动填入地址；或手动填第 2 步的 IP、端口 `7788`、配对码照抄电脑端 → 保存。
   |   |   |
   | - | - |
6. **验证**：设备端显示「已连接 x.x.x.x:7788」；电脑端 `netstat -ano | findstr :7788` 能看到 `ESTABLISHED`；点「下一页」PPT 有反应。

| 现象            | 原因 / 处理                                                      |
| ------------- | ------------------------------------------------------------ |
| 搜索电脑搜不到       | Windows 常把热点识别为「公用网络」并拦入站 → 点电脑端 **防火墙放行**（需管理员确认），再点 **刷新** |
| 地址显示的是别的网卡    | 电脑多网卡会列多个 IP，用 **扫码连接** 窗口切换，或按第 2 步 `ipconfig` 手动填          |
| 手表搜不到 / 连不上热点 | 确认在「标准模式」、热点是 2.4GHz、密码正确；部分手表需先在手机上用运动健康 App 辅助配网           |
| 能连上但点了没反应     | 配对码不一致（电脑端「重新生成」后要重填），或 PPT 没处于放映状态                          |
| 电脑连上热点后上不了网   | 正常现象，本方案本来就不需要互联网，不影响控制                                      |

> 如果两端都有互联网但互相不可达（例如访客网络隔离），也可以给两端装 Tailscale / ZeroTier 组虚拟局域网，再把虚拟 IP 填进设置页；但那会引入第三方且不符合离线目标，仅作备选。

## Wi-Fi Direct 直连（电脑没有热点 / 蓝牙时）

**适用**：电脑开不了 Windows 移动热点、也没有蓝牙，但**有支持 Wi-Fi Direct 的 WiFi 网卡**。不需要手机开热点、不需要路由器或互联网。

电脑用 Wi-Fi Direct 的 Legacy AP 能力广播一个**普通 WiFi 网络**（`EzyLink-Direct`），手机 / 手表用系统 WiFi 连上后就在同一个局域网里，用的还是原来的 TCP `7788` + UDP `7789`。**手机 / 手表端不需要任何改动或新权限**，手表用普通 WiFi 即可。

步骤：

1. **电脑端**：主界面「Wi-Fi Direct 直连」→ 勾选启用。界面会显示网络名称与密码，点「复制热点信息」可复制。
2. **手机 / 手表**：系统设置 → WiFi → 选择 `EzyLink-Direct`，输入密码连接（密码就是电脑端主界面显示的**8 位数字配对码**）。若提示「无互联网」，选择**保持连接**（本方案不需要互联网）。
3. **电脑端**：点 **启动服务** → **刷新**；连上后「设备连接地址」通常显示 `192.168.137.1`。
4. **手机 / 手表端易通遥**：设置页点 **搜索电脑** 自动填址，或手动填第 3 步地址 + 端口 `7788` + 配对码 → 保存。也可在电脑端点「扫码连接」切换地址后扫码。
   |   |   |
   | - | - |
5. **验证**：设备端显示「已连接 192.168.137.1:7788」；电脑 `netstat -ano | findstr :7788` 有 ESTABLISHED。

| 现象                   | 原因 / 处理                                                                       |
| -------------------- | ----------------------------------------------------------------------------- |
| 搜不到 `EzyLink-Direct` | 确认电脑 WiFi 网卡支持 Wi-Fi Direct、**Windows 移动热点已关闭**（二者互斥）、通道状态为 Started；部分网卡需更新驱动 |
| 连上就自动断开              | 系统因「无互联网」回落到其它网络 → 在 WiFi 设置里选择保持连接 / 关闭智能网络切换                                |
| 搜得到电脑但连不上            | 点电脑端 **防火墙放行**（规则覆盖所有网络配置文件），再点 **刷新**                                        |
| 通道启动失败               | 看主界面失败原因；开启过 Windows 移动热点后需先彻底关闭它再重试                                          |
| 提示密码过短 / 一直连不上       | 默认配对码已是 8 位；若你手动把配对码改短过，改回 8 位以上再重新连接（热点密码会同步变化）                              |

> 热点密码**就是电脑端配对码本身**（默认 8 位纯数字），不再带 `EzyLink-` 前缀；重新生成或手改配对码后密码同步变化，已连过的设备需要重新输入。  
> 8 位满足 WPA2 最低密码长度要求。从旧版 6 位配对码升级时电脑端会自动生成新码并提示，手机 / 手表端需重新扫码或更新配对码。  
> 本机实测：WinRT 广告与 Legacy AP 均能启动，虚拟网卡 `Microsoft Wi-Fi Direct Virtual Adapter #2` 为 Up 且分配 `192.168.137.1`；**SSID 在手机上的可见性与真机连通性仍需你确认一次**（Windows 不会在自身扫描结果里列出自己广播的热点）。

## 蓝牙直连（不需要网络）

没有 WiFi、也开不了热点时，可以改走蓝牙：

1. 先在 Windows 系统蓝牙设置里，把电脑与手机 / 手表**配对**一次。
2. 电脑端主界面 → 勾选 **启用蓝牙 RFCOMM 通道**，界面会显示本机蓝牙 MAC 与通道 UUID。
3. 手机 / 手表端扫码（二维码已带蓝牙 MAC），或在设置页「电脑蓝牙 MAC」里手动填写。
4. 设置页连接方式选 **自动** 或 **仅蓝牙**，保存后会自动连上。

- 与 WiFi 通道共用同一套配对码鉴权；电脑端两条通道可同时开启，移动端自动择优。
- 同样是点对点直连，不经过任何服务器，也不需要互联网。
- Android 12 及以上首次使用会请求「附近的设备」（`BLUETOOTH_CONNECT`）权限；拒绝仅影响蓝牙，WiFi 不受影响。

## 扫码连接

不用查 IP、不用手抄配对码，扫一下就完事：

1. 电脑端先点 **启动服务**（二维码里包含当前端口与配对码，必须先启动）。
2. 点 **扫码连接**，弹出二维码窗口。
3. 手机 / 手表端点主界面的 **扫码连接**，对准屏幕扫。
4. 识别成功后自动填入 IP / 端口 / 配对码并立即连接，返回主界面即可控制。

- 电脑有多个网卡 / 多个 IP 时，窗口里可切换不同地址（热点网段优先），扫对应那张即可。
- 二维码窗口提供「复制地址」，不便扫码时可复制后手动粘贴到移动端设置页。
- **全程离线**：二维码只在本地生成与识别，画面不上传、不联网。

二维码载荷格式见 `Protocol.md` 的「扫码连接（二维码载荷格式）」一节：

| 前缀     | IP     | 端口     | 配对码     | 蓝牙 MAC（可选） |
| ------ | ------ | ------ | ------- | ---------- |
| `YTY1` | `<IP>` | `<端口>` | `<配对码>` | `<蓝牙 MAC>` |

## 沉浸模式（手表 / 手机端）

放映 PPT 时，沉浸模式把整屏变为纯黑，  
靠「盲操作」完成全部控制，全程**保持常亮、不会自动息屏**，也**不会被系统自动关闭**。

| 操作                 | 效果            |
| ------------------ | ------------- |
| 轻触**上半屏**          | 上一页           |
| 轻触**下半屏**          | 下一页           |
| **长按上半屏**（约 0.6 秒） | 进入 / 退出放映（切换） |
| **长按下半屏**（约 0.6 秒） | 关闭沉浸模式，返回主界面  |

手表端额外支持**旋转表冠控制翻页**（仅沉浸模式）：

| 表冠动作      | 效果  |
| --------- | --- |
| **顺时针**旋转 | 上一页 |
| **逆时针**旋转 | 下一页 |

- 采用 Wear OS 标准旋转输入（`ACTION_SCROLL` + `AXIS_SCROLL`），纯 framework API，未引入依赖；
- 转动量按档位累计，满一档触发一次翻页，快速转动不会一转跳多页；中途反向转动会重置累计；
- HW Watch 4 实测上报方向与固件定义相反，故 `ImmersionActivity` 的 `CROWN_INVERT` **默认已为 `true`**；  
  若你在其它机型上发现方向相反，改回 `false` 即可。

### 手表端：

手表端沉浸模式进入后**屏幕完全不发光**，系统的抬腕亮屏不会暴露操作：

- Android / Wear OS 采用**把窗口亮度压到最低**的方式，屏幕也看不见任何内容；
- 同时保留 `FLAG_KEEP_SCREEN_ON`，并监听 `ACTION_SCREEN_ON`，一旦系统点亮就立刻压回亮度；
- **反馈全部走震动**，不显示任何文字：进入 60ms / 翻页 18ms / 长按 45ms / 拦截返回键 80ms /  
  **指令发送失败 300ms 长震动**（成功时点击瞬间已震动，不重复提示）。

> 手机端不涉及此项——手机没有抬腕亮屏，且手机端仍保留原来的文字提示。

手机端额外支持**音量键等效控制**（操作方法与屏幕上下部完全一致）：

| 按键             | 等效区域                        |
| -------------- | --------------------------- |
| 音量上键：短按 / 按住不放 | 上半屏短按（上一页）/ 上部长按（进入 / 退出放映） |
| 音量下键：短按 / 按住不放 | 下半屏短按（下一页）/ 下部长按（关闭沉浸模式）    |

细节说明：

- 上下两区各占半屏且铺满整屏，圆屏 / 方屏均按屏幕几何自然划分，无需额外适配；
- 每次有效操作都有一次短震动反馈，黑屏下也能确认指令已发出；
- 手指移动超过阈值会自动取消本次操作，避免滑动误触发；
- 进入沉浸模式或切换放映状态时，会短暂显示一行提示后自动隐藏，不留下常亮文字；
- **返回键（手表端含表冠侧键）被拦截**：放映中误触返回不会退出，只有长按下半屏才关闭；
- 沉浸模式下手机端的音量键只用于控制放映，不再调整系统音量；
- 指令仍走原有长连接，因此与常规按钮使用同一套协议与鉴权，无需额外配置。

## 启动与托盘设置（Windows 端主界面「启动与托盘」区）

| 选项         | 作用                    | 实现方式                                                                                           |
| ---------- | --------------------- | ---------------------------------------------------------------------------------------------- |
| 开机自动启动软件   | 随 Windows 登录自动运行本程序   | 写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\YiTongYao`（用户级，无需管理员权限，便携版同样可用）；卸载时自动清除 |
| 启动后自动开启服务  | 打开程序即自动监听端口、等待手表/手机连接 | 程序启动时按设置自动拉起 TCP 服务                                                                            |
| 开机自启时静默到后台 | 由开机拉起时不弹主窗口           | 启动命令带 `--startup` 参数区分；托盘可见则只驻留托盘，托盘隐藏则最小化到任务栏                                                 |
| 隐藏系统托盘图标   | 完全不显示托盘图标             | `NotifyIcon.Visible = false`                                                                   |
| 关闭时最小化到托盘  | 关闭窗口时驻留托盘而非退出         | 勾选「隐藏托盘图标」时自动关闭并禁用此项（否则程序将失去入口）                                                                |

- **托盘图标隐藏后如何唤出**：按全局热键 **Ctrl+Alt+Y** 随时显示 / 收起主窗口（若被其他程序占用，运行日志会提示注册失败）。
- **托盘图标隐藏时的关闭行为**：关闭窗口即退出程序（没有托盘入口，继续驻留会无法唤出）。
- **自启项自愈**：设置里开启了开机自启，但注册表项被安全软件清理或安装路径变化时，程序启动会自动补回正确命令。

## 安全认证（Windows 端主界面「安全认证」区）

仿照窥屿盾（PeekShield）的认证体系，**不含人脸识别 / 快捷验证**，其余方式全部照搬。

### 三类认证方式（可同时登记多种）

| 方式                  | 说明                                      |
| ------------------- | --------------------------------------- |
| 密码                  | 至少 4 位、两次一致；可附带保密问题用于找回                 |
| 系统解锁（Windows Hello） | 调用系统凭据（PIN / Windows Hello / 指纹 / 密码）验证 |
| U 盘                 | 登记一个 U 盘当钥匙，支持「卷序列号」与「令牌文件」两种模式         |

### 按操作保护 + 双因子

- 每种方式可单独勾选它保护哪些操作：**打开主窗口 / 修改安全设置 / 停止服务 / 退出程序**。  
  只有被保护的操作才会弹验证；未配置保护范围的方式视为保护全部操作。
- 开启**双因子**后，需通过两种**不同类别**的方式（知识 / 平台 / 持有）才算解锁。
- 「立即锁定」可随时作废当前会话并收起窗口，下次打开需重新验证。


### 安全强度

- 密码与保密问题答案都只保存 **PBKDF2（31 万次迭代 + 随机盐 + SHA-256）** 加盐哈希，明文不落地；  
  校验走恒定时间比较，抵御计时侧信道。
- 连续 5 次输错后按阶梯递增锁定（1 → 5 → 10 → 30 → 60 → 120 → 240 分钟），解锁窗口实时倒计时。
- **备用解锁口令**：遗忘密码或丢失 U 盘时的兜底入口，在任何验证框输入即可解锁，并会一并清除失败锁定。  
  代码中只存其哈希与专用 Pepper，**明文不进代码、不进产物**。
- 全部配置落在 `%LOCALAPPDATA%\YiTongYao\settings.json`。
- 若同时隐藏了托盘图标，仍可用 **Ctrl+Alt+Y** 唤出并触发解锁（程序始终保留热键入口）。

### 圆屏 / 方屏自适应（手表端）

手表端通过资源限定符实现自适应，未引入任何 AndroidX 控件：

- `Watch/res/values/dimens.xml` 定义默认（方屏）内边距；
- `Watch/res/values-round/dimens.xml` 为圆屏（如华为 Watch 4 Pro 466×466）加大内边距，避免内容被圆形边缘裁切；
- 布局使用 `ScrollView` + `LinearLayout`，内容超出时滚动，天然兼容不同屏幕尺寸。

## 协议要点（详见 Protocol.md）

- 传输：TCP，UTF-8 文本 JSON，**每行一条指令以 `\n` 结尾**。
- 握手：`{"cmd":"auth","token":"配对码"}`，成功后才能执行指令。
- 指令示例：`ppt_next` / `ppt_start` / `ppt_exit` / `ppt_black` / `ppt_white` /  
  `lock` / `sleep` / `shutdown` / `restart`。
- 元指令：`ping`、`info`（返回 IP/MAC/主机名）。
- 每条指令单独建连（connect → auth → 指令 → 读响应），对间歇性连接更健壮。
- 关机 / 重启为高危指令，移动端强制二次确认。

## 开机（Wake-on-LAN）

关机后电脑无法监听 TCP，故「开机」由**移动端主动发送 WoL 魔术包**到电脑 MAC：

- 前置：BIOS/UEFI 开启网络唤醒，网卡属性允许唤醒。
- 移动端「设置」中填写电脑 MAC（Windows 端界面会显示），点「开机(WoL)」。
