# 易通遥（EzyLink）

一套「手表 / 手机 ↔ 电脑」远程控制方案，通过 **WiFi 直连**控制电脑的 **PPT 放映**，  
以及执行**锁屏 / 睡眠 / 关机 / 重启 / 开机（WoL）**&#x7B49;基础操作。

```
┌──────────────┐   WiFi (TCP, JSON)   ┌──────────────┐
│ 手表 APK      │ ───────────────────▶ │  Windows 端   │
│ 手机 APK      │                      │  (TCP 服务)   │
│ (Android)    │ ◀─────────────────── │  执行指令      │
└──────────────┘                      └──────────────┘
   发送指令                               → PPT 快捷键
                                        → 锁屏/关机/重启…
                                        → WoL 接收由手表/手机主动发起
```

## 离线直连（不需要路由器 / 不需要互联网）

**结论：手机 / 手表与电脑只要在同一条网络链路里就能用，这条链路可以是家里路由器，也可以是电脑自己开的热点，双方都不需要接入互联网。**

推荐做法（完全离线）：

1. 电脑端主界面「连接信息」区 → 点 **开启移动热点设置** → 在系统设置里打开「移动热点」。
2. 回到易通遥点 **刷新**，界面会显示热点已开启，并给出推荐的连接地址（通常是 `192.168.137.1`）。
3. 手机 / 手表连上这台电脑的热点。
4. 手机 / 手表端打开易通遥 → 设置页点 **搜索电脑**，会自动列出电脑（UDP 广播发现，端口 **7789**）；也可以手动填第 2 步的地址。
5. 首次连接输入电脑端显示的配对码，之后**打开 App 就自动连好，可以直接用**。

台式机没有无线网卡时：反过来让**手机开热点、电脑连手机热点**即可，其余步骤相同。

> 若「搜索电脑」搜不到或连上无响应，先点电脑端的 **防火墙放行** 按钮（放行 TCP 7788 与 UDP 7789）。这是最常见的原因。安装器安装时已自动添加该规则。

## 扫码连接

不用查 IP、不用手抄配对码，扫一下就完事：

1. 电脑端先点 **启动服务**（二维码里包含当前端口与配对码，必须先启动）。
2. 点 **扫码连接**，弹出二维码窗口。
3. 手机 / 手表端点主界面的 **扫码连接**，对准屏幕扫。
4. 识别成功后自动填入 IP / 端口 / 配对码并立即连接，返回主界面即可控制。

- 电脑有多个网卡 / 多个 IP 时，窗口里可切换不同地址（热点网段优先），扫对应那张即可。
- 二维码窗口提供「复制地址」，不便扫码时可复制后手动粘贴到移动端设置页。
- **全程离线**：二维码只在本地生成与识别，画面不上传、不联网。

二维码载荷格式见 `Protocol.md` 的「扫码连接（二维码载荷格式）」一节：

|        |      |      |          |
| ------ | ---- | ---- | -------- |
| \`YTY1 | <IP> | <端口> | <配对码>\`。 |

## 沉浸模式（手表 / 手机端）

放映 PPT 时，沉浸模式把整屏变为纯黑，  
靠「盲操作」完成全部控制，全程**保持常亮、不会自动息屏**，也**不会被系统自动关闭**。

| 操作                 | 效果            |
| ------------------ | ------------- |
| 轻触**上半屏**          | 上一页           |
| 轻触**下半屏**          | 下一页           |
| **长按上半屏**（约 0.6 秒） | 进入 / 退出放映（切换） |
| **长按下半屏**（约 0.6 秒） | 关闭沉浸模式，返回主界面  |

手表端额外支持**旋转表冠控制翻页**（仅沉浸模式）：

| 表冠动作      | 效果  |
| --------- | --- |
| **顺时针**旋转 | 上一页 |
| **逆时针**旋转 | 下一页 |

- 采用 Wear OS 标准旋转输入（`ACTION_SCROLL` + `AXIS_SCROLL`），纯 framework API，未引入依赖；
- 转动量按档位累计，满一档触发一次翻页，快速转动不会一转跳多页；中途反向转动会重置累计；
- HW Watch 4 实测上报方向与固件定义相反，故 `ImmersionActivity` 的 `CROWN_INVERT` **默认已为 `true`**；  
  若你在其它机型上发现方向相反，改回 `false` 即可。

### 手表端：

手表端沉浸模式进入后**屏幕完全不发光**，系统的抬腕亮屏不会暴露操作：

- Android / Wear OS 采用**把窗口亮度压到最低**的方式，屏幕也看不见任何内容；
- 同时保留 `FLAG_KEEP_SCREEN_ON`，并监听 `ACTION_SCREEN_ON`，一旦系统点亮就立刻压回亮度；
- **反馈全部走震动**，不显示任何文字：进入 60ms / 翻页 18ms / 长按 45ms / 拦截返回键 80ms /  
  **指令发送失败 300ms 长震动**（成功时点击瞬间已震动，不重复提示）。

> 手机端不涉及此项——手机没有抬腕亮屏，且手机端仍保留原来的文字提示。

手机端额外支持**音量键等效控制**（操作方法与屏幕上下部完全一致）：

| 按键             | 等效区域                        |
| -------------- | --------------------------- |
| 音量上键：短按 / 按住不放 | 上半屏短按（上一页）/ 上部长按（进入 / 退出放映） |
| 音量下键：短按 / 按住不放 | 下半屏短按（下一页）/ 下部长按（关闭沉浸模式）    |

细节说明：

- 上下两区各占半屏且铺满整屏，圆屏 / 方屏均按屏幕几何自然划分，无需额外适配；
- 每次有效操作都有一次短震动反馈，黑屏下也能确认指令已发出；
- 手指移动超过阈值会自动取消本次操作，避免滑动误触发；
- 进入沉浸模式或切换放映状态时，会短暂显示一行提示后自动隐藏，不留下常亮文字；
- **返回键（手表端含表冠侧键）被拦截**：放映中误触返回不会退出，只有长按下半屏才关闭；
- 沉浸模式下手机端的音量键只用于控制放映，不再调整系统音量；
- 指令仍走原有长连接，因此与常规按钮使用同一套协议与鉴权，无需额外配置。

## 启动与托盘设置（Windows 端主界面「启动与托盘」区）

| 选项         | 作用                    | 实现方式                                                                                           |
| ---------- | --------------------- | ---------------------------------------------------------------------------------------------- |
| 开机自动启动软件   | 随 Windows 登录自动运行本程序   | 写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\YiTongYao`（用户级，无需管理员权限，便携版同样可用）；卸载时自动清除 |
| 启动后自动开启服务  | 打开程序即自动监听端口、等待手表/手机连接 | 程序启动时按设置自动拉起 TCP 服务                                                                            |
| 开机自启时静默到后台 | 由开机拉起时不弹主窗口           | 启动命令带 `--startup` 参数区分；托盘可见则只驻留托盘，托盘隐藏则最小化到任务栏                                                 |
| 隐藏系统托盘图标   | 完全不显示托盘图标             | `NotifyIcon.Visible = false`                                                                   |
| 关闭时最小化到托盘  | 关闭窗口时驻留托盘而非退出         | 勾选「隐藏托盘图标」时自动关闭并禁用此项（否则程序将失去入口）                                                                |

- **托盘图标隐藏后如何唤出**：按全局热键 **Ctrl+Alt+Y** 随时显示 / 收起主窗口（若被其他程序占用，运行日志会提示注册失败）。
- **托盘图标隐藏时的关闭行为**：关闭窗口即退出程序（没有托盘入口，继续驻留会无法唤出）。
- **自启项自愈**：设置里开启了开机自启，但注册表项被安全软件清理或安装路径变化时，程序启动会自动补回正确命令。

## 安全认证（Windows 端主界面「安全认证」区）

仿照窥屿盾（PeekShield）的认证体系，**不含人脸识别 / 快捷验证**，其余方式全部照搬。

### 三类认证方式（可同时登记多种）

| 方式                  | 说明                                      |
| ------------------- | --------------------------------------- |
| 密码                  | 至少 4 位、两次一致；可附带保密问题用于找回                 |
| 系统解锁（Windows Hello） | 调用系统凭据（PIN / Windows Hello / 指纹 / 密码）验证 |
| U 盘                 | 登记一个 U 盘当钥匙，支持「卷序列号」与「令牌文件」两种模式         |

### 按操作保护 + 双因子

- 每种方式可单独勾选它保护哪些操作：**打开主窗口 / 修改安全设置 / 停止服务 / 退出程序**。  
  只有被保护的操作才会弹验证；未配置保护范围的方式视为保护全部操作。
- 开启**双因子**后，需通过两种**不同类别**的方式（知识 / 平台 / 持有）才算解锁。
- 「立即锁定」可随时作废当前会话并收起窗口，下次打开需重新验证。

### 安全强度

- 密码与保密问题答案都只保存 **PBKDF2（31 万次迭代 + 随机盐 + SHA-256）** 加盐哈希，明文不落地；  
  校验走恒定时间比较，抵御计时侧信道。
- 连续 5 次输错后按阶梯递增锁定（1 → 5 → 10 → 30 → 60 → 120 → 240 分钟），解锁窗口实时倒计时。
- **备用解锁口令**：遗忘密码或丢失 U 盘时的兜底入口，在任何验证框输入即可解锁，并会一并清除失败锁定。  
  代码中只存其哈希与专用 Pepper，**明文不进代码、不进产物**。
- 全部配置落在 `%LOCALAPPDATA%\YiTongYao\settings.json`。
- 若同时隐藏了托盘图标，仍可用 **Ctrl+Alt+Y** 唤出并触发解锁（程序始终保留热键入口）。

## Windows 端安装（NSIS 向导）

双击安装程序，依次经过：**欢迎 → 许可协议 → 组件 → 安装位置 → 安装方式 → 安装 → 完成（可立即运行）**。

- **安装位置**：默认用户级安装到 `%LOCALAPPDATA%\Programs\易通遥`，卸载信息写入 `HKCU`。
- **磁盘与权限校验**：所在分区剩余空间不足 250 MB 或目录不可写时会阻止继续。
- **安装方式**（仅在检测到旧安装时出现）：
  - *标准安装（推荐）*：保留已有设置（端口、配对码），只更新程序文件；
  - *全新安装*：清除 `%LOCALAPPDATA%\YiTongYao` 下的设置与日志，恢复默认（不可恢复，会二次确认）。
- **覆盖安装**：安装前自动结束正在运行的易通遥进程，避免文件被占用。
- **卸载**：开始菜单 / 控制面板 → 易通遥 → 卸载，可勾选「删除配置信息」「清空运行日志」。

构建安装器：

```bash
# 1) 先发布程序到 dist/publish
cd Windows/YiTongYao.Windows
dotnet publish -c Release -r win-x64 --self-contained true -o ../../dist/publish

# 2) 再编译 NSIS（PROJECTROOT 传项目根目录绝对路径）
makensis /DPROJECTROOT="E:/workbuddy/易通遥" installer_source/yitongyao.nsi
```

## 手表 / 手机 端构建与安装

APK 采用**免 Gradle / 免 Maven** 的纯框架层构建（aapt2 + d8 + apksigner），  
只需本机装有 **Android SDK** 与 **JDK 17**：

```bash
# 设置 Android SDK 路径（按本机实际修改）
set ANDROID_SDK_ROOT=E:/android-sdk
# 构建手表端、手机端（缺省两者都构建）
python Tools/build_apk.py watch
python Tools/build_apk.py phone
# 或直接双击 Tools/build_apk.bat
```

产物落在 `Watch/watch-release.apk`、`Phone/phone-release.apk`。  
安装到设备：

```bash
adb install Watch/watch-release.apk        # 手表（或华为 Watch 4 Pro 侧载）
adb install Phone/phone-release.apk        # 手机
```

> HW Watch 4 Pro 运行 HarmonyOS：先在手表开启「开发者模式 / ADB 调试 / 通过 WLAN 调试」，  
> 再用 `adb connect <手表IP>:5555` 后 `adb install` 侧载；本端不含 GMS 依赖，可正常安装运行。

### 圆屏 / 方屏自适应（手表端）

手表端通过资源限定符实现自适应，未引入任何 AndroidX 控件：

- `Watch/res/values/dimens.xml` 定义默认（方屏）内边距；
- `Watch/res/values-round/dimens.xml` 为圆屏（如华为 Watch 4 Pro 466×466）加大内边距，避免内容被圆形边缘裁切；
- 布局使用 `ScrollView` + `LinearLayout`，内容超出时滚动，天然兼容不同屏幕尺寸。

## 协议要点（详见 Protocol.md）

- 传输：TCP，UTF-8 文本 JSON，**每行一条指令以 `\n` 结尾**。
- 握手：`{"cmd":"auth","token":"配对码"}`，成功后才能执行指令。
- 指令示例：`ppt_next` / `ppt_start` / `ppt_exit` / `ppt_black` / `ppt_white` /  
  `lock` / `sleep` / `shutdown` / `restart`。
- 元指令：`ping`、`info`（返回 IP/MAC/主机名）。
- 关机 / 重启为高危指令，移动端强制二次确认。

## 开机（Wake-on-LAN）

关机后电脑无法监听 TCP，故「开机」由**移动端主动发送 WoL 魔术包**到电脑 MAC：

- 前置：BIOS/UEFI 开启网络唤醒，网卡属性允许唤醒。
- 移动端「设置」中填写电脑 MAC（Windows 端界面会显示），点「开机(WoL)」。

## 已知范围与后续

- 当前以 **WiFi** 直连为主通道，已支持「电脑开热点 + 设备直连」的完全离线场景。
- 手表 / 手机 APK 构建依赖 Android SDK 工具链（aapt2/d8/apksigner），已用本机 SDK 实机构建验证。

## 隐私

- 配对码默认随机生成并存于本机 `LocalApplicationData/YiTongYao/settings.json`（Windows 端）；  
  移动端设置存于 App 私有 `SharedPreferences`。
- 不收集任何个人数据，不联网到第三方服务器，仅在本机网络内点对点通信。
- **扫码连接不涉及图像留存**：相机画面只在内存中用于实时解码，不写文件、不传输。
